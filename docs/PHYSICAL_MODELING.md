# 零采样的岭南丝竹：在浏览器里用物理建模“造”一把高胡

> 这是一篇面向对声音合成感兴趣的读者的技术随笔。工程参数与节点级实现见
> [音频引擎架构](./ARCHITECTURE.md)，源码在
> [`src/utils/audioSynth.ts`](../src/utils/audioSynth.ts)。

## 一、缘起：不加载一个音频文件，能做出民族乐器吗？

「岭南丝竹 · Gongche Studio」要让人在网页里弹奏高胡、扬琴与潮州筝，还要跟着工尺谱视唱。
常规做法是**采样合成**（sampling）：请乐手把每个音录一遍，播放时按音高变速回放。它简单、
逼真，但有三个绕不开的代价：

1. **体积与版权**：三件乐器、数十个音、多种技法，采样包动辄数十到数百 MB，且录音版权
   需要谨慎处理；
2. **表现力被“冻”在录音里**：换把滑音、揉弦深度、击弦力度一旦录死，交互时很难连续改变；
3. **与“工尺谱教学”这个主题气质不合**：我们更想展示的是“声音为什么是这样”，而不是
   一堆黑盒音频。

于是我们选了更难但更有趣的路线：**物理建模合成（physical modeling synthesis）**——
不录音，而是用算法描述“弦如何振动、琴体如何共鸣、弓毛如何摩擦”，让声音在浏览器里
被实时“算”出来。整个项目没有任何 `.wav/.mp3` 音色文件。

## 二、三条合成路线，各自的位置

| 路线 | 代表 | 优点 | 短板 |
| --- | --- | --- | --- |
| 减法 / 加法合成 | 经典模拟合成器、`OscillatorNode` | 计算极轻、连续可控 | 像“电子音”，难有真实乐器的复杂瞬态 |
| 采样合成 | 绝大多数软件音源 | 开箱即真 | 体积大、版权重、表现力受限于录音 |
| 物理建模 | 数字波导、模态合成、源-滤波器 | 体积小、可连续操控、能解释发声机理 | 参数调校难、需要一点信号处理功底 |

Web Audio API 恰好提供了物理建模所需的“积木”：振荡器、各类滤波器、延迟、卷积器
（`ConvolverNode`）、增益与压缩器，以及可以逐采样写入的 `AudioBuffer`。

## 三、拨弦：一根延迟线，就是一根弦

弹拨乐器（扬琴、筝）的核心模型是 **Karplus-Strong 数字波导（digital waveguide）**。
它的物理直觉非常优美：一根理想弦的振动，可以用“一个声音在延迟线里来回传播”来近似。

最小化的 Karplus-Strong 只有两步：

1. 用一段短促噪声（长度约等于一个基频周期）填满延迟线，模拟拨弦 / 击弦瞬间弦被拨动的形状；
2. 反复读取延迟线，每次读出时做一个一阶低通再喂回去：

```
y[n] = 0.5 · (x[n] + x[n-1])      // 取相邻两点平均 = 一阶低通
```

每绕环路一圈，高频就被磨掉一点、能量就衰减一点——于是你听到一个自然“由亮变暗、由强变弱”
的拨弦音。延迟线长度 `N ≈ 采样率 / 基频` 决定音高。

### 朴素模型不够像，我们做了这些改进

真实的扬琴和潮州筝比理想弦复杂，引擎里的 `renderPluckedString()` 在此基础上补了几件事
（参数对照见 [架构文档 §3](./ARCHITECTURE.md#3-弹拨弦鸣改进型-karplus-strong-波导)）：

- **分数延迟 + 线性插值**：延迟长度不再是整数个采样，于是音高可以连续滑动——潮州筝左手
  按滑、吟弦时的滑音不会“阶梯化”失真；
- **按周期计的 T60 衰减补偿**：信号每绕一圈恰为一个振动周期，我们按“圈”而不是按“采样”
  施加损耗，并补偿环路低通在基频处的能量损失，让低音的余音天然比高音长（T60 ∝ 1/f）；
- **同度双弦微失谐**：扬琴每个音有两根弦，把两条波导分别调偏 ±4 音分再叠加，就出现了
  真实扬琴那种缓慢起伏的“合唱感”（beatings）；
- **击 / 拨瞬态**：起音混入几毫秒宽带噪声（琴竹或指甲触弦）与一个很高频的正弦“叮”声
  （金属光泽），瞬态是耳朵辨认乐器的关键线索；
- **琴体共振峰整形**：用峰化滤波器叠加音板 / 琴箱的共鸣频带，而不是用带通把泛音砍平。

潮州筝“以韵补声”的左手作韵，则是一条动态音高包络：起音张力上提、随后按滑压向目标音
（活五调最深约 1.5 个半音）、再延迟渐入揉弦——这正是采样很难连续给出、而波导几乎免费
就能做到的表现力。

## 四、拉弦之难：弓弦不是“拨一下”

既然波导这么好用，高胡为什么不直接照搬？这是被问得最多的问题，也是整个项目最关键的
一次选型。

**Karplus-Strong 描述的是“一次性激励、随后自由衰减”的系统**，和拨弦 / 击弦完全吻合。
但高胡是**弓弦乐器**，物理图景截然不同：

- 弓毛靠松香的“粘-滑”（stick-slip）效应**持续向弦注入能量**，音量可以一弓拉十几秒而
  几乎不衰减；
- 真实弓弦存在 **Helmholtz 运动**：弦在弓段呈“两个直线段 + 一个拐角（Helmholtz 角）
  来回折返”的周期运动，弓压、弓速、触弦点都会改变它；
- 音色里始终裹着一层**弓毛摩擦噪声**，且一弓之内可以连续换把、走出多个音（连弓）。

若把朴素波导用于高胡，你会得到一个“拨弦味”的、起音后不断衰减的音，既没有持续弓压，
也没有摩擦质感，更难做一弓多音的连贯线条。要在波导里补齐这些，需要带非线性弓-弦接触
模型的**双向波导**（如 Waveguide 的 bowed string 模型），实现与调参成本都高得多。

### 高胡的折中方案：谐波谱声源 + 弓噪 + 共振峰

我们为高胡选择了更适合实时交互、听感也更可控的**“声源 + 滤波”式弓弦模型**：

1. **声源**：用 `PeriodicWave` 直接给定 13 个谐波的幅度，基频与低次谐波都很强、高次缓慢
   衰减，对应钢弦、小琴筒、紧蟒皮的明亮频谱；
2. **弓噪**：一小段循环的**粉噪**经高通、再经一个中心频率跟踪基频的带通，叠在声源上，
   只提供“擦弦质感”而不喧宾夺主。起弓瞬间略强、随后压低，连弓换把时轻轻一闪；
3. **琴筒共振峰**：声源与弓噪并联后，依次通过 1100 / 2300 / 3800 Hz 三个峰化频段和
   7 kHz 的高频空气峰，再切掉无用的低频浑浊。

> **一条重要经验：共振峰要“增强”而不是“滤除”。**
> 早期版本用宽带带通去“抠”琴筒频率，结果把泛音大片砍掉，高胡听起来又闷又暗。改成
> peaking / highshelf **叠加**共鸣后，泛音被保留、琴箱色彩被点亮，通透感立刻出来了。

### 连贯与“韵味”，藏在包络里

广东音乐的灵魂是线条与润腔。模型用一个长寿命的“弓段（voice）”承载整段连弓旋律：

- **连弓复用**：连续触发新音时不重新起弓，而是让振荡器与弓噪带通做 75 ms 指数滑音，
  弓压平稳保持——音与音之间是一条歌唱性的线，没有音量断崖；
- **起弓绰音**：起音从下方约 0.35 个半音在 55 ms 内快速贴住准音高，既有粤胡的“绰注”
  韵味，又不会让人觉得系统性偏低；
- **延迟揉弦**：起弓 120 ms 后才开始 5.2 Hz 的揉弦、380 ms 达到全幅（约 ±20 音分），
  对称波动不带来音高漂移——这也修正了“揉弦导致音偏低”的听感；
- **自然收弓**：末音先平稳延续，再指数淡出后才释放节点，而不是戛然而止。

界面层因此能支持**按住音位持续拉弦、按住拖过相邻音位换把、键盘空格 / 回车演奏**——
交互方式本身也在模仿弓弦乐器。

## 五、空间感：用一段“算出来的房间脉冲响应”做卷积

三件乐器都汇入同一条主总线。为了得到室内乐的厅堂感，我们没有加载任何真实采样的
脉冲响应（IR），而是**程序化生成一段 2.8 秒的立体声 IR**：左右声道各布置若干不同时刻的
早期反射声，再接一条指数衰减的噪声尾，然后交给 `ConvolverNode` 做卷积。干声与少量湿声
并联，最后过一道总线压缩器粘合音色、防止削顶。这样既保持“零音频资源”，又能让声音
“落进一个房间里”。

## 六、听对了，还要“识得”：自相关测音高

视唱玩法需要把麦克风里的人声实时翻译成工尺字。我们在时域做**自相关（autocorrelation）**：
声音近似周期信号，把信号与自身的延迟副本对齐，相关度最高处的延迟就是基音周期；再对峰值
做**抛物线插值**获得亚采样精度，从而得到稳定的基频。随后按当前调式（正线 1=C 或五声羽调
1=D）把频率映射到最近的工尺字，并算出音分偏差与置信度。游戏里“偏高 / 偏低多少音分”
的实时反馈，用的就是这条链路。

## 七、工程化：让声音“可复现、可测试”

物理建模参数多、主观调参容易“改了 A 坏了 B”，我们用两个工程手段把它稳住：

- **波导核心写成纯函数**：`renderPluckedString(sampleRate, frequency, options)` 不依赖
  浏览器、返回 `Float32Array`，随机数用带种子的 mulberry32——同参数逐采样一致。于是它
  能在 Node / Vitest 里离线渲染并断言：没有 NaN、峰值电平合理、尾音相对音头充分衰减、
  基频误差在阈值内、活五滑音深度约 1.5 半音；
- **渲染结果按“乐器:音高:采样率”缓存为 `AudioBuffer`**：交互时同音复用，波导只在首次
  计算，实时性能毫无压力。

高胡基于实时 Web Audio 节点、无法在 Node 直接渲染，测试里用一份**数学等价的离线复刻**
（相同的谐波谱、滤波器系数与包络时序）锁定其基频与连弓滑音行为。这套“乐理断言 + 声学
断言”目前有 59 项测试，参数改动一旦破坏音高或衰减规律，CI 会立即失败。

## 八、局限与未来（诚实地说）

这个引擎追求的是“小体积、可交互、有神似的岭南韵味”，而非声学实验室级别的精确：

- 高胡尚未实现带非线性弓-弦接触的**双向波导 / commuted synthesis**，弓压与触弦点的细微
  影响目前由谐波谱与包络近似；
- 琴筒共鸣与厅堂 IR 都是**程序化构造**，没有使用真实琴体 / 厅堂采样；
- 揉弦、滑音的风格参数是针对广东音乐听感调校的经验值，未必覆盖所有流派与演奏家。

这些恰好也是继续探索的方向：更真实的弓弦接触模型、按技法切换的弓法、以及更多岭南乐器
（椰胡、洞箫、秦琴……）。欢迎在 [ARCHITECTURE.md](./ARCHITECTURE.md) 的基础上一起调参、
补测试、提 PR。
